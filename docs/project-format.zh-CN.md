# Compositor 工程格式，版本 1–11

> 🌐 **English**：[docs/project-format.md](docs/project-format.md) ｜ 简体中文（当前文件）

`.comp` 文件是一个 macOS 文档包，其中包含 `manifest.json` 和一个 `images/` 目录，目录内是按 `<layer UUID>.png` 命名的资产。

manifest 标识为 `com.compositor.project`，新保存的版本号为 `11`（版本 `1`–`10` 仍然可读），采用 sRGB 工作色彩空间。它存储文档 UUID、像素尺寸、激活图层 UUID，以及从下到上排列的图层。每个图层存储 UUID、名称、可见性、变换（origin、size、顺时针旋转、翻转、采样方式）以及可选的图像文件名。空白图层没有图像资产。

内嵌的 PNG 保留源像素和透明度；变换信息独立存储。工程在被移动或删除导入的源照片后仍能存活。保存采用协调的原子包替换。在替换活动文档之前，不支持的版本、无效的元数据、缺失的资源、不安全的路径以及过大的数据都会被拒绝。

限制：画布/图像每边最多 30,000 像素，源像素总数 1 亿，最多 10,000 个图层，manifest 最大 4 MiB，每个编码资源最大 512 MiB。校验逻辑详见 `ProjectStore.swift`。

撤销历史与视口仅在会话内有效。打开时让画布适配窗口、恢复选区并以干净的历史记录开始。未来可编辑的特性必须扩展 schema 并通过往返测试。PNG 导出是平面化的衍生品，不会标记工程被保存过。

Image Size 增加了可选的 `resolution`（像素/英寸，1–9600）。旧 manifest 若没有该字段则默认为 72。这个累加字段保持了对版本 1 的兼容性。PNG 与 JPEG 导出都会包含文档分辨率元数据。重新采样会存储新的图层像素与原始图层，撤销仅保留当前会话期间的原始来源。

版本 2 在图层记录中增加了可选的 `parentID` 与 `isGroup`。组没有图像文件。根节点没有父节点；子节点引用已存在的组。数组顺序定义从下到上的兄弟顺序；渲染器按连续子树的方式遍历每个组。可见性被继承而不改变子标志。循环引用、缺失/非组的父节点、携带图像的组，以及超过 64 层祖先的嵌套都会被拒绝。组祖先为最深层的叶子节点预留空间。组元数据在图像/画布缩放与裁剪后保持不变。旧版本的应用会拒绝版本 2 而非错误地渲染分组文档。折叠状态不会被序列化。

版本 3 在每个图层上增加了可选的 `opacity`（有限 0–1）与 `blendMode`（Normal、Multiply、Screen、Overlay、Darken、Lighten、Difference、Color Dodge、Color Burn）。缺失字段默认为完全不透明与 Normal 混合模式。组记录在版本 8 之前要求这些默认值；版本 8 允许文件夹自带不透明度；文件夹的不透明度会与内部每个图层相乘，而混合模式保持 Normal，因为文件夹是透传的。效果在合成过程中应用，并在调整源大小时作为元数据保留。声明为更早版本的文件不能包含非默认的外观值。

版本 4 在单个图层上增加了可选的 `maskFile` 与 `maskEnabled` 字段。蒙版文件名必须是 `<layer UUID>.mask.png`，位于 `images/` 目录；当蒙版存在时 `maskEnabled` 默认为 true。没有蒙版的记录省略这两个字段。此版本中组不能携带蒙版。声明版本 1–3 的文件不能包含蒙版元数据。

蒙版存储 8 位灰度覆盖度（无 alpha，白色显示，黑色隐藏）。其归一化范围与图像的本地矩形匹配，因此同一图层的变换对两者都生效。统一 1×1 的蒙版是合法的，可在绘制前避免分配全分辨率像素。非均匀蒙版像素及其缩略图是历史记录共享的不变资产。图像字节调整会随图像变化重采样蒙版；画布大小与裁剪保持其像素不变。除了已有的 1 亿图像像素外，最多还可存储 1 亿蒙版像素；单边与单文件限制也适用于蒙版。禁用的蒙版仍会被嵌入且可编辑，但不影响合成。图层与蒙版之间的目标选择仅在会话内有效，重新打开时回到图像像素。

版本 5 增加了可选的 `maskSourceID`：以文档坐标提供实时 alpha 的非组图层的 UUID。它与已启用的光栅蒙版相乘以决定目标 alpha。源像素、变换、不透明度、光栅蒙版和上游实时蒙版共同决定覆盖范围；可见性与 RGB 颜色不影响。源图层保持独立。缺失引用、自引用、循环引用、组作为端点，以及超过 256 个节点的链都会被拒绝。删除操作可以将实时覆盖烘焙到依赖图层像素中（保留其光栅蒙版），也可以移除链接，作为单次可撤销操作。链接在图像/画布调整大小与裁剪后保持不变。旧版本默认为无实时蒙版；旧版本应用会拒绝版本 5。

UI 术语：这些 alpha 链接就是剪贴蒙版。Option 点击可以为下方兄弟图层设置基底或解除连接。多个被剪贴的图层共享一个基底，缩进显示在它之上，当被移到连续堆栈之外时会解除。其底层 `maskSourceID` 表示不变。

版本 6 允许组记录上存在 `maskFile` 与 `maskEnabled`。文件夹没有图像，因此其蒙版覆盖文件夹自身的变换矩形（即文件夹创建时的画布大小）；图像字节调整会通过该变换重新采样蒙版，画布大小与裁剪保持其像素，与图层蒙版完全一致。文件夹是透传的，因此启用的文件夹蒙版会与每个后代图层自身的蒙版以及任何嵌套父文件夹的蒙版相乘来决定覆盖范围；剪贴蒙版覆盖不受影响。声明版本 1–5 的文件不能为组指定蒙版，旧版本应用会拒绝版本 6。

版本 7 增加了调整图层：图层记录带有一个可选的 `adjustment` 对象且没有 `imageFile`。调整图层不能是组，也不能携带 `text`；与任何图层一样，它接受变换、不透明度、混合模式、光栅蒙版与剪贴链接，并影响其文件夹内下方合成的所有内容。`kind` 是以下之一：`Hue/Saturation`、`Levels`、`Curves`、`Exposure`、`Gradient Map`、`Grain`、`Invert`、`Black & White` 与 `Color Balance`（版本 9 又增加了三种）。记录中每种类型的所有设置都是可选的，并默认为 identity 调整：Hue/Saturation 的 `hue`（±360）、`saturation` 与 `lightness`（±100），`colorize` 与 `hsvSettings`；`levels`（四个通道范围，依次为 RGB、红、绿、蓝）；`curves`（四个通道点列表）；`exposureSettings`；`gradientMapSettings`（`shadows`、`highlights`、`reversed`）；`grainSettings`；`blackWhiteSettings`；`colorBalanceSettings`。超出范围或非有限值都会被拒绝。声明版本 1–6 的文件不能包含调整记录，旧版本应用会拒绝版本 7。具体范围详见 `LayerAdjustment.swift`。

版本 8 允许文件夹自带 `opacity`，会与其内部每个图层相乘；文件夹的混合模式保持 Normal，因为文件夹是透传的（声明版本 1–7 的文件要求文件夹为完全不透明）。它还增加了可选的顶层 `guides` 数组，其中是对齐参考线，每条都有 `id`、`axis`（`horizontal` 或 `vertical`）以及 `position`（文档像素，有限，最大幅度 1,000,000）。最多存储 1,000 条参考线；声明版本 1–7 的文件不能包含参考线。参考线在画布大小与裁剪时通过偏移来跟随画布。

版本 9 增加了三种对相邻像素采样的调整类型：`Gaussian Blur`（`blurRadius`，0.1–250 文档像素）、`Motion Blur`（`motionAngle`，−90 到 90 度，以及 `motionDistance`，1–2000）以及 `Add Noise`（`noiseAmount`，0.1–400，`noiseGaussian`、`noiseMonochromatic` 与 `noiseSeed`，使图案在多次会话间保持稳定）。声明版本 1–8 的文件不能包含这些类型；早期调整类型在版本 7 及以上仍然有效。

版本 10 允许文字图层使用不同颜色绘制部分字符：在其 `text` 元数据中可使用可选的 `colorRuns`（参见可编辑文字）。声明版本 1–9 的文件不能使用该字段。

版本 11 允许这些字符也使用不同字体：在同一元数据中使用可选的 `fontRuns`。声明版本 1–10 的文件不能使用该字段。从版本 10 开始 `colorRuns` 仍然有效。

### 累加的图层字段

较新的字段是可选的，且不以版本号作为门槛；旧读取器会忽略这些字段并保持像素或链接的蒙版不变：

- `maskPlacement` 与 `maskLinked`：未链接的蒙版（`maskLinked` 为 false；缺失表示已链接）将其自身变换保留在 `maskPlacement`（一个文档空间的矩形，类似图层变换）中，不再跟随图层移动。两者都需要 `maskFile`。
- `shape`：使用形状工具创建的图层保留其样式（`kind`、`red`/`green`/`blue`、圆角半径 `cornerRadius`（文档像素），以及线条的 `lineWidth` 与 `start`/`end`（占图层框的比例）），以便在缩放时干净地重绘。其 PNG 仍是普通光栅图像；一旦其他任何东西更改这些像素，元数据就会被丢弃。

### 可编辑文字

像素图层记录可包含可选的 `text` 元数据：内容、PostScript 字体名、像素字号、RGB 颜色、对齐方式、字距、行距，以及可选的 `boxSize` 段落边界。文本在这些边界内换行；改变它们会重排文本而不会缩放字体。PNG 仍然作为显示与导出回退。旧读取器忽略此元数据。变换、复制、蒙版与画布大小调整会保留它；破坏性像素操作会将文字栅格化，并在下次保存时省略元数据。缺失字体在编辑时使用系统字体，而保存的 PNG 在此之前保留原始外观。从版本 10 开始，可选的 `colorRuns` 列出使用与该文本自身 `red`/`green`/`blue` 不同颜色着色的字符：每个 run 使用 UTF-16 单位下的 `location` 与 `length`，以及 `red`、`green` 与 `blue`（0–1）。从版本 11 开始，可选的 `fontRuns` 列出使用不同于 `fontName` 字体的字符：同样的 `location` 与 `length`，加上 `fontName`。两种 run 都是排序的，长度为正，且在内容范围内结束；任何 run 之外的字符使用文本自身的颜色或字体。

### 图层效果

可选的 `effects` 记录包含独立的 `stroke`、`shadow`、`colorOverlay`、`innerShadow`、`outerGlow` 与 `innerGlow` 记录。Stroke 包含大小（0–500 图层像素）、颜色、不透明度以及一个 `inside` 标志（描边位于边的内侧还是外侧）；drop shadow 与 inner shadow 各包含角度、距离、模糊、颜色与不透明度；color overlay 包含颜色与不透明度；outer glow 与 inner glow 各包含大小（0–500 图层像素）、颜色与不透明度。每个效果都支持可选的 `enabled` 可见性（缺失即默认可见）；隐藏的效果仍保留所有参数，并列在其图层之下。效果（包括它们的可见性）会被保存并参与文档撤销。画布预览在串行后台 worker 上运行，使用共享的像素预算；导出时以全分辨率渲染效果。省略某项效果的记录意味着该图层没有该效果，旧读取器只会看到它们理解的效果而忽略其余部分。
