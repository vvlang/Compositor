# Compositor 工程格式，版本 1–11

`.comp` 文件是一个 macOS document package，里面是 `manifest.json` 和一个 `images/` 目录（装着 `<layer UUID>.png` 资源）。

清单里写入 bundle identifier `com.compositor.project`，新存为版本 `11`（版本 `1`–`10` 仍可读），工作色域为 sRGB。它保存文档 UUID、像素尺寸、当前图层 UUID，以及按从底到顶顺序排列的图层。每个图层保存自己的 UUID、名字、可见性、变换（原点、尺寸、顺时针旋转、翻转、采样方式）以及可选的图片文件名。空白图层没有图片资源。

内嵌的 PNG 保留源像素与透明度，变换则单独存储。工程在源图被移动或删除后依然可用。保存使用协调的原子包替换。不支持的版本、无效的元数据、缺失的资源、不安全的路径以及过大的数据，都会在替换当前文档前被拒绝。

限制：画布 / 图像每边 30000 像素，总源像素 1 亿，最多 10000 层，清单 4 MiB，每个编码资源 512 MiB。校验逻辑在 `ProjectStore.swift`。

撤销历史与视图状态都是会话级。打开时自动适配窗口、恢复选区，并以干净的历史启动。未来要新增可编辑特性，必须扩展模式并加入往返测试。PNG 导出是展平后的派生文件，不会标记工程为已保存。

Image Size 新增可选的 `resolution`（像素/英寸，1–9600）。没有它的旧清单默认为 72。这个附加字段保持版本 1 兼容。PNG 与 JPEG 导出都会带文档分辨率元数据。重采样会存新的图层像素与边界；撤销只在当前会话内保留先前的源数据。

版本 2 给图层记录加入可选的 `parentID` 和 `isGroup`。文件夹没有图片文件。根节点没有父节点，子节点引用一个已存在的文件夹。数组顺序决定兄弟层从底到顶的排列，渲染器把每个文件夹当作一棵连续子树来遍历。可见性继承，但不会改写子节点的标志。循环引用、缺失或非文件夹的父节点、带图片的文件夹，以及超过 64 层祖先的嵌套都会被拒绝。文件夹祖先给最深处的叶子层留出空间。文件夹元数据会跨过图像与画布的调整和裁剪。旧版本构建会拒绝 v2 而不是错误地渲染分组文档。折叠状态不参与序列化。

版本 3 加入每个图层可选的 `opacity`（有限值，0–1）与 `blendMode`（Normal、Multiply、Screen、Overlay、Darken、Lighten、Difference、Color Dodge、Color Burn）。缺省字段默认为全幅与普通混合。分组记录当年也要求该默认值，直到版本 8 才允许文件夹自带不透明度；文件夹的不透明度作用于内部每一个图层，而混合模式保持普通——文件夹是「透传」。效果在合成过程中应用，并在源数据被调整时作为元数据保留。声明更低版本的文件不能包含非默认值。

版本 4 在每个图层上加入可选的 `maskFile` 和 `maskEnabled` 字段。蒙版文件名必须是 `images/` 里的 `<layer UUID>.mask.png`；没有蒙版时 `maskEnabled` 默认 true。没有蒙版的记录省略这两个字段。分组在本版本中不能带蒙版。声明版本 1–3 的文件不能包含蒙版元数据。

蒙版保存 8-bit 灰度覆盖图，不带 alpha 通道（白色显示，黑色隐藏）。归一化的范围与图像的局部矩形相同，因此同一套图层变换对两者都适用。1×1 的统一蒙版是合法的，可避免在绘制前就分配完整分辨率的像素。非统一蒙版像素与缩略图都是被历史共享的不可变资源。Image Size 用图像变换调参；Canvas Size 和 Crop 保留原像素。除了原来的 1 亿图像像素外，最多还可存 1 亿蒙版像素；蒙版也受单边与单文件限制。停用的蒙版块仍嵌入且可编辑，但不会影响合成。图像/蒙版目标的选择属于会话状态，重开时回到图像像素。

版本 5 加入可选的 `maskSourceID`：一个非分组图层的 UUID，它以文档坐标提供实时 alpha。它与目标启用的栅格蒙版一起乘到目标的 alpha 上。源像素、变换、不透明度、栅格蒙版以及上游的实时蒙版都参与覆盖；可见性与 RGB 颜色不参与。源本身仍是独立图层。缺失引用、自指、循环引用、分组终点以及超过 256 个节点的链路都会被拒绝。删除时可以把实时覆盖烘焙进依赖图层的像素（保留其栅格蒙版），也可以解除链接，整套操作可作为一个撤销步骤。链接在图像/画布调整和裁剪过程中保留。旧版本默认为没有实时蒙版；旧版本构建会拒绝 v5。

UI 术语：这些 alpha 链接就是剪贴蒙版。Option-单击可让下层兄弟作为基座，或解除这种连接。多个被剪贴的图层共用一个基座，在它上方以缩进方式显示，移出连续堆叠范围就会解除。底层的 `maskSourceID` 表示保持不变。

版本 6 允许分组的 `maskFile` 和 `maskEnabled`。文件夹没有图片，因此其蒙版覆盖的是文件夹自身的变换矩形（创建文件夹时的画布尺寸）；Image Size 通过该变换调参，Canvas Size 和 Crop 则保留原像素，与图层蒙版规则一致。文件夹是「透传」，启用的文件夹蒙版会与所有后代图层的蒙版以及外层文件夹的蒙版逐层相乘；剪贴蒙版覆盖不受影响。声明版本 1–5 的文件不能给分组蒙版，旧版本构建会拒绝 v6。

版本 7 加入调整图层：图层记录带可选的 `adjustment` 对象且没有 `imageFile`。调整图层不能是分组也不能带 `text`；它和其他图层一样带变换、不透明度、混合模式、栅格蒙版和剪贴链接，且影响其文件夹内位于它下方的所有合成结果。`kind` 是 `Hue/Saturation`、`Levels`、`Curves`、`Exposure`、`Gradient Map`、`Grain`、`Invert`、`Black & White`、`Color Balance` 之一（版本 9 又加三种）。记录保存每种调制的设置，可选且默认为恒等调整：`hue`（±360）、`saturation` 与 `lightness`（±100）、`colorize` 与 `hsvSettings`（用于 Hue/Saturation）；`levels`（四个通道的范围，RGB 然后红绿蓝）；`curves`（四个通道的控制点列表）；`exposureSettings`；`gradientMapSettings`（`shadows`、`highlights`、`reversed`）；`grainSettings`；`blackWhiteSettings`；`colorBalanceSettings`。超出范围或非有限的值会被拒绝。声明版本 1–6 的文件不能包含调整记录，旧版本构建会拒绝 v7。具体的取值范围见 `LayerAdjustment.swift`。

版本 8 允许文件夹自带 `opacity`，它作用于内部每个图层；文件夹的混合模式仍为普通（因为文件夹是「透传」——声明 1–7 的文件要求文件夹为全幅）。同时新增可选的顶层 `guides` 数组，存放对齐参考线，每条包含 `id`、`axis`（`horizontal` 或 `vertical`）以及 `position`（文档像素，必须是有限值，绝对值不超过 1,000,000）。最多存储 1,000 条参考线；声明 1–7 的文件不能包含参考线。Canvas Size 和 Crop 通过让参考线随画布偏移来保留它们。

版本 9 加入三种会采样邻近像素的调整类型：`Gaussian Blur`（`blurRadius`，0.1–250 文档像素）、`Motion Blur`（`motionAngle`，−90 至 90 度，加 `motionDistance`，1–2000）以及 `Add Noise`（`noiseAmount`，0.1–400，`noiseGaussian`、`noiseMonochromatic`、`noiseSeed`，所以两次会话之间噪点图案稳定）。声明 1–8 的文件不能包含这些类型；之前的调整类型在版本 7 及以上仍然合法。

版本 10 让文字图层可以给部分字符涂不同颜色：在其 `text` 元数据里加入可选的 `colorRuns`（见「可编辑文字」）。声明 1–9 的文件不能包含它。

版本 11 让这些字符也能用不同的字形：在同一元数据里加入可选的 `fontRuns`。声明 1–10 的文件不能包含它。`colorRuns` 在版本 10 起仍然合法。

### 附加图层字段

后续字段都是可选的，并且不以版本号为门槛，所以旧版本读取时会直接忽略、保留像素或蒙版链接：

- `maskPlacement` 与 `maskLinked`：未链接的蒙版（`maskLinked` 为 false，缺失即视为链接）会在 `maskPlacement` 里保留自己的变换——一个文档空间矩形，结构与图层变换类似——移动图层时不再跟随。两者都要求 `maskFile` 存在。
- `shape`：用形状工具创建的图层保留其样式（`kind`、`red`/`green`/`blue`、文档像素单位的 `cornerRadius`，以及直线的 `lineWidth` 与作为图层盒比例的 `start` 和 `end`），这样在缩放时能干净地重绘。它的 PNG 仍是普通光栅；一旦其他东西改动了这些像素，元数据会随之被丢弃。

### 可编辑文字

像素图层记录可以包含可选的 `text` 元数据：内容、PostScript 字体名称、像素单位的字号、RGB 颜色、对齐、字距、行距，以及可选的 `boxSize` 段落边界。文字在这些边界内自动折行；修改它们会让文字重新折行，而不会缩放字体。PNG 仍然作为显示与导出的兜底。旧版本读取时会直接忽略这段元数据。变换、复制、蒙版、画布尺寸修改都会保留它；破坏性的像素操作会把文字栅格化，并在下次保存时省略元数据。编辑时缺失字体临时用系统字体，但保存的 PNG 在此之前保留原外观感。从版本 10 起，可选的 `colorRuns` 列出与文字自身的 `red`/`green`/`blue` 不同的颜色上色字符：每段包含 `location` 与 `length`（UTF-16 单位），以及 `red`、`green`、`blue`（0–1）。从版本 11 起，可选的 `fontRuns` 列出与 `fontName` 不同的字形：同样的 `location` 与 `length`，加上 `fontName`。任一类型的下划线均按顺序排列、不重叠，长度为正且不超出文字；落在所有下划线之外的字符使用文字本身的颜色或字体。

### 图层样式

可选的 `effects` 记录里保存独立的 `stroke`、`shadow`、`colorOverlay`、`innerShadow`、`outerGlow`、`innerGlow` 记录。Stroke 保存尺寸（0–500 像素）、颜色、不透明度和 `inside` 标记（指定描边位于路径的哪一侧）；Drop Shadow 与 Inner Shadow 各保存角度、距离、模糊、颜色与不透明度；Color Overlay 保存颜色与不透明度；Outer Glow 与 Inner Glow 各保存尺寸（0–500 像素）、颜色与不透明度。每条都支持可选的 `enabled` 可见性（缺失即视为可见）；隐藏的效果保留参数，并仍列在图层下。效果（含其可见性）会被保存，并参与文档撤销。画布预览由一个串行的后台 worker 渲染，共享像素预算；导出则按全分辨率渲染。某条记录省略某个字段，意味着该图层没有这个效果，旧版本就能只看到它能理解的效果而忽略其余。
